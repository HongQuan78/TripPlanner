### Pass 3b — user reverses the search architecture (same day)

- (override by user) **the modal overlay and the chosen-destination bar are cut.** User (verbatim): "tại sao lại có cái 'change' như thế? tôi chỉ cần 1 thanh search và khi search sẽ hiển thị gợi ý sổ ra kiểu dropdown là được rồi thôi mà?" — i.e. one search bar, typing shows a dropdown, that is all.
- (note) the facilitator had offered the command-palette overlay as one of three options and the user selected it earlier in this pass; on seeing it specified they judged it over-built. Correction accepted without argument — the simpler design is also the better one.
- (insight) "Change" only existed as a consequence of the overlay: once the field lives inside a modal there is no field on the page, so something must reopen it. Remove the modal and the affordance has no reason to exist — changing city is just typing in the bar. Likewise the chosen-destination bar duplicated a fact already stated twice (the input's value and the "Attractions near {name}" heading), so it was solving a problem the overlay had created.
- (decision) committed search architecture = **the shipped one, kept**: one inline `<form role="search">` with one input in the hero band, leading magnifier, inline clear that appears only when there is a value, primary submit at the right edge, and the existing suggestion dropdown anchored beneath it. No trigger, no modal, no summary row.
- (decision) the `/` keyboard shortcut and its hint chip are dropped — clutter on a hero whose one control is now a visible, obvious field.
- (decision) **the multi-row location result list is deleted with no successor.** Consequence handled: a typed submit now shows its matches in the same dropdown rather than filling a list in the page body, so the dropdown becomes the only place candidate matches ever render — which is the rule that makes the reported symptom unreproducible.
- (consequence) EXPERIENCE.md's "there are no modals" rule is **restored**, and the whole dialog obligation set introduced earlier in this pass is deleted rather than satisfied: no `role="dialog"`/`aria-modal`, no focus trap, no focus restoration, no scroll lock, no background inertness mechanism, no `aria-activedescendant`-versus-trap hazard.
- (consequence) the CRITICAL landmark finding evaporates: keeping the bar a `<form role="search">` preserves the search landmark for free, rather than needing a wrapper to restore what the trigger-plus-dialog would have destroyed.
- (consequence) the icon-only-submit resolution is no longer needed. Because the submit now sits *beside* an input rather than inside a button, it is a real control with its own accessible name — no nesting, no duplicate tab stop, no presentational compromise.
- (consequence) the commit-announcement finding flips resolution: with no summary row to move focus to, an `aria-live="polite"` message on choice is now the right mechanism rather than the focus-move alternative.
- (decision) the two defect fixes that carry the actual work are unchanged and now more prominent, since this pass no longer rewrites the component: defect 1's missing blur/outside-click handlers must be added (with care that blur does not fire before an option's mousedown), and defect 2's suppression mechanism is deleted outright rather than repaired.

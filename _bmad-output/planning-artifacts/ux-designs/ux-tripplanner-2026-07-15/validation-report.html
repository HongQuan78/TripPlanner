medium resolved

Clear button in the hero band had no committed appearance or contrast strategy

DESIGN.md — Components → Hero search; FE/src/pages/SearchPage.module.css:79–101
The shipped transparent primary-blue ghost would float bare on arbitrary photography — the one band element outside the ink-scrim/solid-white rule that DESIGN's own Do's and Don'ts enforce; the spine committed only its typography, not its fill.
Resolution: Committed as a decision: the Clear button drops its transparent ghost inside the band and takes a solid {colors.surface-container-lowest} fill behind its {colors.primary} 1px border and text (6.73:1 on white), hover → {colors.surface-container-low} — a documented divergence from the shipped ghost, forced by the text-over-photography rule.
medium resolved

Disabled Search button had three contradictory treatments (token, prose, shipped code)

DESIGN.md — frontmatter button-primary / Components; FE/src/pages/SearchPage.module.css:74
EXPERIENCE keeps "Search stays disabled while the input is empty"; the background-disabled token said {colors.disabled} with {colors.on-primary} text (the 1.70:1 combination the Components prose itself calls unreadable); shipped code uses 50% opacity on the primary fill. This disabled button is the resting state of the pre-search hero — the page's most prominent moment.
Resolution: The shipped 50%-opacity primary fill is now the committed treatment in the Hero search bullet ("the shipped treatment, now the committed one — never the {colors.disabled} gray wash"); the button-primary.background-disabled token was updated to match, and {colors.disabled} is explicitly reserved for inert chrome elsewhere.
low resolved

Literal "shadow-sm" instead of {shadows.sm} in the auth-card bullet

DESIGN.md — Components → Auth card
Resolved by inference but broke the reference syntax every other bullet uses.

Prior gate — accessibility review (WCAG 2.2 AA)

review-accessibility.md

The auth-run accessibility review computed a full contrast table from the committed hexes and found three highs — outline-variant placeholders at 1.70:1, the pending button label rendered in the exempt-but-unreadable disabled style with no live-region announcement, and a hero gradient whose 80%→0 ramp could not protect the 18px body line above the bottom band — plus mediums on the double-signaling password toggle, the "decorative to assistive tech" hero copy claim, the non-persistent verify live region, the input-border boundary contrast, and the all-net-new ARIA commitments. All were applied at the auth finalize step: placeholders dropped, the pending state keeps the full primary fill with the label swap announced, the ≥65%-through-copy gradient floor was committed (and is now reused verbatim by the home hero band), the toggle carries a single signal (changing name, no aria-pressed), the hero copy is aria-hidden, and verification status renders inside one persistent role="status" container. The accessibility lens was declined for this home update by user decision; the home-update rubric verified the new load-bearing contrast combinations numerically in its stead.

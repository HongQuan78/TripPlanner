# Story 5.16: Redesign the Trips list and Trip detail against the Horizon "Boarding Pass" spine pair

Status: review

## Story

As a Trip Planner user managing my trips,
I want the Trips list (`/trips`) and Trip detail (`/trips/:id`) rebuilt in the Horizon "Boarding Pass" language — a grid of travel-pass cards with a derived status/countdown, and an itinerary rendered as a journey rail of day segments under a summary ticket,
so that a list of trips reads as a timeline of what's coming and a trip reads as a route, while every shipped data hook, state, and accessibility contract is preserved and no backend change is required.

## Context

Source of truth: the spine pair at `_bmad-output/planning-artifacts/ux-designs/ux-tripplanner-2026-07-16-trips/` — `DESIGN.md` (Horizon · Boarding Pass visual tokens/components) and `EXPERIENCE.md` (IA, behavior, states, derived values, accessibility). The mockup `mockups/key-trips-and-detail.html` is a spine-derived reference; **the spines win on conflict**, and the Horizon token layer already shipped in `FE/src/index.css` is the final arbiter of every hex/radius/shadow/motion value.

This pair **extends Horizon** (`ux-tripplanner-2026-07-15`, already shipped app-wide by stories 5-12/5-13/5-14). It introduces **no new hex, no new fonts, no new dependencies, and no new data** — the "Boarding Pass" richness is built entirely from the existing trip payload plus the current local date. The trip payload is exactly `id`, `name`, `startDate`, `endDate`, `tripDays[]` (each `{ day, destinations[] }`); a destination is `id`, `name`, `rating` (int), `category`, `xid` (nullable), `openingHours`, `cuisineType`, `isHalalFriendly`. **There is no trip cover image and no city/location field** — no surface may imply one.

Working mode is **refine-and-elevate, not re-architect** (explicit spine decision): the routes, IA, data hooks (`useTrips`, `useTrip`, `useRemoveDestinationFromDay`), inline `CreateTripForm`/`EditTripForm`, the shipped `ConfirmDialog` removal contract, `StarRating`, and every load-bearing state (loading/error/empty/not-found/creating/editing/remove-pending/remove-error) are **preserved and restyled** — only the visual structure and reading order change. Both surfaces stay inside `AppLayout` chrome. The list preserves the API's returned order (no sorting/grouping). Because a destination can only be added from a real attraction (`AddToTripDialog` needs an `xid`), the new per-day "＋ Add destination" affordance is a **handoff to discovery** (navigate to `/`), never a nested text editor — preserving the invariant that every planned destination originates from a real attraction.

## Acceptance Criteria

1. **Derived-value utilities (payload + today).** Pure, unit-tested helpers compute every derived value from loaded data plus the user's local calendar date, never a request: `daysBetween` (date-only), a `todayISO()` local-date accessor, `formatShortDate` ("12 Aug"), `formatSegmentDate` ("Tue · Aug 12"), a `tripStatus(startDate, endDate, today)` returning the kind (`upcoming`/`ongoing`/`past`) + human label ("In 27 days" / "Tomorrow" / "Ongoing · Day 3" / "Past") per the spine's rules, and a count singularizer ("1 day"/"5 days", "1 place"/"9 places"). Edge cases (trip spanning today, single-day trip, start===today, zero destinations) are covered.

2. **Trips list — pass grid.** Each trip renders as a `{components.trip-pass}`: a `{rounded.lg}` white surface with `{colors.outline-variant}` hairline and `{shadows.sm}`, clipped, with a `6px` left accent spine filled with the `{colors.primary}`→`{colors.tertiary}` gradient (flat `{colors.outline-variant}` when the trip is **past**). The head carries the trip name (`{typography.card-name}`, 1.1rem/800) with the `{components.status-pill}` top-right and a `{components.pass-route}` beneath (start short-date · dashed connector with an `aria-hidden` `✈` · end short-date). A dashed perforation line with two `{colors.background}` notches separates the head from the `{components.pass-stub}` on a `{colors.surface-container-low}` fill: exactly two stats, **Days** (=`tripDays.length`) and **Places** (=summed destinations), each an ink `{colors.on-surface}` value over an uppercase `{colors.on-surface-variant}` `{typography.stat-label}`. The shipped `auto-fill, minmax(16rem, 1fr)` grid, `1rem` gap, 40ms staggered entrance, and hover-lift to `{shadows.lg}` with `translateY(-4px)` are kept. Trips render in **API order**, unchanged.

3. **Status pill.** `{rounded.full}`, `{typography.status-pill}` (10.2px/800, mixed-case), three variants with AA-verified token pairings: *upcoming* = `{colors.on-secondary-container}` on `{colors.secondary-container}`; *ongoing* = `{colors.success}` on `{colors.success-container}`; *past* = `{colors.on-surface-variant}` on `{colors.surface-container}` (no `{colors.outline}` text, no whole-pass opacity dimming). The label text is derived at render from dates vs. today and is part of the pass link's accessible text (never a separate `aria-label`). Past trips are de-emphasized via the muted pill + desaturated grey spine only, with all text at full strength.

4. **Trip detail — summary ticket.** The detail header is a `{components.summary-ticket}`: `{rounded.lg}` white surface, hairline, `{shadows.sm}`, `7px` accent-gradient spine, **no** hover-lift. Top row: the trip name as the page's single `<h1>` in `{typography.display-name}` (24px/800) with the shipped `formatDateRange` beneath in `body-md` `{colors.on-surface-variant}`, and the "Edit trip" `{components.outline-button}` top-right. A dashed-hairline divider, then a stat row of three: **Days**, **Places**, and the **Unplanned hint** — value in `{colors.secondary}` reading "N days unplanned" (`count(tripDays where destinations.length === 0) > 0`), flipping to `{colors.success}` "All days planned" at zero; never red/scolding. Editing toggles the inline `EditTripForm` (kept behavior); while editing, the form replaces the ticket body and the Edit button is hidden.

5. **Trip detail — journey rail.** Days render in payload order as `{components.day-segment}`s hung from a single `2px` `{colors.outline-variant}` vertical `{components.journey-rail}` (gutter `26px`, tightened below `md`). Each segment: a `16px` `{rounded.full}` node straddling the rail (3px `{colors.primary}` ring, white fill; **solid `{colors.primary}` fill + `{colors.surface-container-high}` halo when the day is today and the trip is ongoing**, `aria-hidden` decoration); a head with the day date as an `<h2>` in `{typography.seg-date}` ("Tue · Aug 12", uppercase), the `{components.today-marker}` "Today" pill beside it (only when today & ongoing), and a `{colors.secondary-container}` count pill ("2 places", singularized, only when non-empty); the day's destination rows; then the `{components.add-day-button}`. A day with zero destinations shows the `{components.empty-day}` treatment ("No destinations planned for this day yet.") in place of rows, with the add-day button beneath.

6. **Destination row.** Each destination is a `{components.destination-row}`: `{rounded.md}` row on `{colors.background}` with a `{colors.outline-variant}` hairline, the name in `body-md` weight 700, the shipped Horizon category chip, the shipped `StarRating`, and the `{components.remove-button}` (`{colors.error}` on `{colors.error-container}`, kept) pushed to the trailing edge. If `xid !== null` the name is a `<Link>` to `/attractions/:xid` and hover shifts the row hairline and name to `{colors.primary}`; if `xid === null` the name is plain non-interactive text and the row does not shift. The row is **not** itself a link — the name link and Remove are the only targets (no nesting).

7. **Add-destination handoff.** Each day segment ends with a `{components.add-day-button}`: a `{rounded.md}` slot with a dashed `{colors.primary}` border on transparent, `{colors.primary}` text, a leading `＋`, and the visible label "Add destination" (hover fill `{colors.surface-container-low}`). It is a real `<button>` with a self-sufficient accessible name including its day context (`aria-label="Add a destination to {formatted date}"`). Activation **navigates to `/`** (the discovery/search surface) — it never opens a nested picker or drops a raw text field. (The optional trip/day deep-link pre-select is explicitly **not** built this run and is not faked as dead UI.)

8. **Remove flow + deterministic focus.** Removal keeps the shipped `ConfirmDialog` contract exactly ("Remove {name} from this day?", danger, pending state, one pending mutation at a time). A **failed** removal surfaces the kept inline error line above the rail carrying `role="alert"` so it is announced on insertion; focus returns to the still-present Remove button. On **successful** removal the triggering button is destroyed with its row, so focus moves to a deterministic anchor — the parent day segment's `<h2>` (made programmatically focusable) — never left to fall to `<body>`. **Cancel** returns focus to the Remove button.

9. **Accessibility floor (no regression + additions).** The whole pass is a single `<a>` to `/trips/:id` whose accessible name is its visible text in reading order (name → status → route dates → stats), with the route dates composed as a range via a visually-hidden "to" and decorative glyphs (`✈`, accent spine, rail node) `aria-hidden`; no duplicate `aria-label`, so each fact announces once. Heading outline is kept: `/trips` one `<h1>` "My trips"; `/trips/:id` the trip name as `<h1>` and each day date as `<h2>` (the summary ticket adds no competing heading). Status is never color-only (each carries a word); the today signal is never color-only (the visible "Today" pill + the word "Today" folded into the day `<h2>` accessible name; the lit node is `aria-hidden`). Remove keeps `aria-label="Remove {name}"`; the add-day button is never an unlabeled "＋". The 2px `{colors.primary}` focus ring from `index.css` stays visible on passes, name links, Remove, add-day, and Edit. The Remove and add-day controls meet a ≥24px AA hit floor (2.5.8) via padding with a 44px goal; on narrow viewports the row wraps its trailing controls under the name rather than shrinking them. Skeletons stay `aria-hidden` behind the kept visually-hidden "Loading your trips…" live text.

10. **States preserved & restyled.** `/trips`: loading (the 4 `aria-hidden` skeletons, geometry updated to the pass silhouette so the swap does not jump; visually-hidden "Loading your trips…" kept), error (⛅ + "Could not load your trips. Please try again." + "Try again" `refetch`), empty (🧳 "No trips yet" + invitation + "Create your first trip", hidden while the create form is open), creating (inline `CreateTripForm`, "New trip" hidden while open). `/trips/:id`: invalid/not-found id (🙈 "Trip not found" + the ownership-privacy copy, verbatim), loading ("Loading trip…"), service error (⛅ + kept copy + "Try again"), editing, empty-day, all-unplanned. None removed; each restyled into the Boarding Pass language.

11. **Quality gates.** `npm test`, `npm run lint`, and `npm run build` pass in `FE/`. Existing `TripsPage`/`TripPlannerPage` tests are updated to the new structure/copy (short-date route on the list; segment-format day `<h2>`s on the detail). New tests cover the derivation helpers, the derived status pill (upcoming/ongoing/past via a fixed system time), the stub/ticket counts and singularization, the unplanned hint (N / "All days planned"), the today marker + `<h2>` accessible-name suffix, the add-day handoff navigation + `aria-label`, and the deterministic remove-focus behavior.

## Dev Notes

- **No new tokens/deps.** Everything references the existing `--color-*`, `--radius-*`, `--shadow-*`, `--duration-*`, `--ease-spring` custom properties in `FE/src/index.css`. Do not add hex, fonts, or npm packages. The single decorative gradient is `linear-gradient(var(--color-primary), var(--color-tertiary))` on the accent spine only.
- **Today derivation & tests.** The page computes `today = todayISO()` (local calendar date) at render; `tripStatus`/today-node are pure functions of `(payload, today)` and never tick. Because status/today depend on the real clock, tests that assert a specific pill or the Today marker wrap the render in `vi.useFakeTimers()` + `vi.setSystemTime(new Date('YYYY-MM-DDT..'))` and restore real timers after. Keep `tripStatus`'s `today` an explicit argument so `dates.test.ts` can test it purely.
- **Timezone safety.** Parse `YYYY-MM-DD` via `Date.UTC(y, m-1, d)` (not `new Date(str)`, which is UTC-midnight but drifts when formatted in a negative-offset zone) and read weekday with `getUTCDay()`. `todayISO()` builds the string from `getFullYear/getMonth/getDate` (local) so "today" matches the user's wall calendar. Date-string comparisons use lexicographic `<`/`>` on the zero-padded ISO strings (correct for equal-length ISO dates).
- **Pass is one link; accessible-name composition.** The status pill, route dates, and stub are presentational text *inside* the `<a>` — no nested interactive elements, no per-part `aria-label`. Compose the route as "12 Aug<vh> to </vh>16 Aug" (visually-hidden "to" from `Skeleton.module.css .visuallyHidden` or a local equivalent) so the link name reads as a range. The `✈` glyph and the spine/notches/node are `aria-hidden`/pure CSS.
- **List route vs. detail range.** The list pass shows compact `formatShortDate` dates ("1 Aug"); the detail ticket keeps the full `formatDateRange` ("Aug 1, 2026 – Aug 2, 2026"). The old list test asserting the full range on `/trips` must move to the short-date form.
- **Day `<h2>` = seg-date + Today.** Render the day heading as `<h2 class=segDate>` containing the "Tue · Aug 12" text and, when today & ongoing, an inline `{components.today-marker}` "Today" pill *inside* the h2 so its accessible name becomes "Tue · Aug 12 Today" (satisfies 1.4.1/1.3.1 without an aria override). The count pill lives in the segment head as a **sibling** of the h2 (counts are not headings). Make the h2 focusable (`tabIndex={-1}` + ref) as the post-remove focus anchor.
- **Deterministic remove-focus.** Track which day a removal belongs to; on a successful settle move focus to that day's `<h2>` ref. On cancel or failure, focus returns to the Remove button (default browser behavior already returns focus to the trigger on `ConfirmDialog` close; verify and, if needed, restore it explicitly). Do not let focus fall to `<body>`.
- **Add-day handoff.** Baseline honest behavior only: `useNavigate()` → `navigate('/')`. Do **not** ship the optional trip/day deep-link pre-select (it would need `SearchPage`/`AddToTripDialog` wiring out of scope here) — omit rather than fake. The button's `aria-label` includes the day so it is self-describing.
- **Star rating & category chip.** Reuse the shipped `StarRating` (three-glyph "Rated N of 3", gold `#b5780f`) and the existing category chip styling unchanged — the destination row only restyles its container/hover, not these.
- **Skeleton silhouette.** Add a pass-shaped skeleton class in `TripsPage.module.css` (head + stub proportions, `{rounded.lg}`) instead of the generic 14rem `Skeleton.card`, so the loading→loaded swap does not jump. Keep it `aria-hidden` behind the kept visually-hidden live text.
- **jsdom has no layout.** The accent-spine gradient, perforation notches, rail line/node, hover-lift, sticky nothing (there is none here), and reduced-motion collapse are CSS-only — asserted structurally in unit tests and recommended for Playwright visual QA (desktop + mobile) at review, consistent with 5-13/5-14/5-15.
